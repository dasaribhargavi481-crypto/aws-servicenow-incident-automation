
# ServiceNow Incident Examples

This document shows example incidents that could be created from cloud monitoring alerts.

## Example 1: High CPU Usage

- Incident Short Description: AWS Alert - High-CPU-Usage
- Category: Software
- Impact: 2 - Medium
- Urgency: 2 - Medium
- Description: CPU utilization exceeded 80 percent.
- Suggested Action: Check CPU usage and investigate the application workload.

## Example 2: Server Health Alert

- Incident Short Description: AWS Alert - Server-Health
- Category: Software
- Impact: 2 - Medium
- Urgency: 2 - Medium
- Description: A sample server health alert needs investigation.
- Suggested Action: Review monitoring data and check service availability.

## Example 3: Alarm Resolved

- Incident Short Description: AWS Alert - Alarm-Resolved
- Description: The monitoring alarm returned to the OK state.
- Suggested Action: Review the existing incident and update its status according to the team's process.

## Note

These are sample scenarios for documentation only. No real ServiceNow incidents have been created or tested.



## Example Incident 2: High Memory Usage

- **Incident Number:** DEMO002
- **Short Description:** High Memory Usage Alert
- **Priority:** High
- **Category:** Software
- **Source:** AWS CloudWatch
- **Description:** Memory usage exceeded the configured threshold.
- **Suggested Action:** Check memory utilization and investigate the affected service.

## Example Incident 3: Service Unavailable

- **Incident Number:** DEMO003
- **Short Description:** Application Service Unavailable
- **Priority:** Critical
- **Category:** Software
- **Source:** AWS CloudWatch
- **Description:** An application health alarm indicates that the service may be unavailable.
- **Suggested Action:** Investigate application logs, service health, and recent changes.

## Note

These are sample incidents for demonstration only. They are not real incidents created in ServiceNow.
